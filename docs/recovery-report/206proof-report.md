# 206proof.com archive recovery checkpoint

**Updated:** 2026-10-20 UTC. This is a source-acquisition checkpoint, not a completed or published reconstruction. The site generations remain separate: the 2007 Vanilla 1.1.3 site, the 2008–2012 Vanilla `/forum/`, the 2012–2013 community routes, and the 2013–2014 vBulletin `/4um/` forum.

## Archive index coverage

The Wayback CDX query `206proof.com/*` was fetched uncollapsed with a 20,000-row limit and no resume key. It returned 19,874 capture events across all indexed statuses; 17,910 events have status 200. This establishes completion of that exact CDX query as returned, not all possible aliases, subdomains, external media hosts, or material absent from the archive. Both parsed responses, their query metadata, and response SHA-256 values are in `recovery/206proof/all-events-all-status.json`, `all-events-all-status.cdx.json`, `all-events-200.json`, and `all-events-200.cdx.json`.

The all-status response spans 2007–2026. Later parked, injected, and placeholder content is retained as index evidence but is excluded from the historical site editions. HTTP 200 alone is not treated as proof of usable page or media content.

## Validated source material saved

`recovery/206proof/recovered-resources.json` currently records 7,516 attempts: 7,460 payloads passed format checks and 56 responses were rejected or undecodable. The validated records include:

- 6,163 HTML documents from the 2007 Vanilla site, 2008–2012 `/forum/`, 2012–2013 community routes, and 2013–2014 `/4um/` forum.
- 1,162 images and 128 CSS files, including Vanilla theme/extension styles, smileys, uploaded account pictures, community profile images, and vBulletin dependencies.
- Seven MP3 files with recognizable MP3 frame/ID3 signatures: six `SongOfTheWeek` uploads indexed in December 2010 and `poopintags.mp3` indexed in 2013. They are local preservation evidence only; playable redistribution has not been reviewed or approved.
- 6,741 unique SHA-256 payload hashes occupying 188,885,300 bytes. Identical payloads share content-addressed files.

Every attempt retains requested timestamp, original URL, CDX metadata, resolved replay URL/actual timestamp when available, MIME/type validation, byte length, hash, local path, and errors. Fifty-six failures remain recorded: empty responses, invalid content encoding, off-target responses, and failed image candidates. Most are external web addresses mistakenly indexed as paths beneath `/forum/`, unusable root alternates, or empty historical endpoints. The selected 2012 `DiscussionID=15250&page=1` response returned 1,181 bytes but failed full-HTML validation; its exact URL has only one status-200 CDX row. The three image dependencies `nl.jpg`, `triple.jpg`, and `new.png` have only short `text/html`/empty responses in the indexed captures, not valid image payloads. Failures are not counted as recovered pages.

The content-addressed payload bytes under `recovery/206proof/raw/` are retained in this workspace and excluded from Git; the tracked manifest and indexes preserve provenance, but a fresh checkout does not contain those response bodies and must reacquire them before building this edition.

The 2008–2012 Vanilla selector identifies 5,137 distinct exact URL records with query strings and host aliases preserved. All 5,137 selected route/date records have now been attempted; none remain queued. Captured forum pages include accounts, discussion listings, and exact pagination variants (including long threads with more than 20 pages). Some selected records failed full-document validation or had empty responses and remain explicit failures in the manifest. The route set is dominated by accounts and discussions. The 39-page `DiscussionID=988` thread and the 2013 vBulletin/community routes have separate records; this selector does not merge them into the Vanilla edition.

Do not replace these gaps with guessed content. Revisit exact YouTube/SoundCloud source URLs and media history, recording an archive miss separately from a failed request.
